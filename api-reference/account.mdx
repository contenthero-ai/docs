Base URL `https://app.contenthero.ai/api/v1`. All endpoints take a bearer API key. The tables on this page are generated from the route contract: the Scope column is the scope the key needs, and `None` means any valid key.

## Your account

`PATCH /account` sets `spendCap`, the monthly spend cap in credits (`null` removes it). That field needs the `billing:write` scope and the account's owner.

{/* rest:begin account */}

| Method | Path | Scope | Purpose |
| --- | --- | --- | --- |
| `GET` | `/account` | None | Your balance, what is available, credits reserved for work in progress, this month's spend, the spend cap, the plan and auto top-up. |
| `PATCH` | `/account` | Varies: each field names its own scope; `spendCap` needs `billing:write` | Update your account. Only the fields you pass change. `spendCap` sets the monthly cap in credits, or `null` for none. |

<AccordionGroup>

<Accordion title="PATCH /account">

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `spendCap` | integer or null |  | The monthly spend cap in credits, or null for no cap. |

</Accordion>

</AccordionGroup>

{/* rest:end account */}

```bash
curl https://app.contenthero.ai/api/v1/account \
  -H "Authorization: Bearer $CONTENTHERO_API_KEY"
```

## Status, view and link formats

`GET /status/{id}` is the one place to follow any background job: pass the id the starting call returned.

{/* rest:begin utilities */}

| Method | Path | Scope | Purpose |
| --- | --- | --- | --- |
| `GET` | `/status/{id}` | Varies: decided by what the id names: a generation or edit needs `studio:generate`, an export needs `editor:read`, the other kinds need none | The status of any background job in one shape: a generation or edit, an export, a brand kit read, an avatar, a post's analysis or scene map, a transcript, an import. |
| `GET` | `/view` | `context:read` | What you are looking at in the open app (surface, focus, selection, and with `capture` a picture of the screen), and your own work rendered from the saved project. |
| `GET` | `/link-formats` | None | The link contract: the grammar of app addresses and every linkable noun, so a caller can build a link from a noun and an id. |

<AccordionGroup>

<Accordion title="GET /status/{id}">

**Query**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `kind` | `output` \| `export` \| `brand_kit` \| `avatar` \| `content` \| `scenes` \| `transcript` |  | Which kind of job the ids name. Only for a full UUID, scenes, a transcript, or an id the answer says is ambiguous. |

## Cost preflight

There is no separate pricing endpoint. Every generation can be previewed for free by passing `getCost: true` (SDK and MCP) or `--cost` (CLI) on the generate call. The preflight takes the same parameters as the real call, so the quote matches the charge. See [Account & Billing](/account-billing).

## Usage attribution

Spends made with an API key are attributed to that key. Per-key usage is visible in the API Keys view in the app.
