The ContentHero skill is an installable set of workflows for your agent. It turns ContentHero into a context-and-execution layer your agent already knows how to use well: how to ground a draft, how to chain a generation, how to prompt each model, how to assemble and publish. It runs inside your agent (Claude, Cursor, Codex, and more) and drives the MCP, CLI, or raw API underneath.

The repo is [`contenthero-ai/skills`](https://github.com/contenthero-ai/skills).

<Note>
It was three skills (`contenthero-generate`, `contenthero-pipeline`, `contenthero-brand`) until September 2026. One skill now covers the same ground with a single install. If you have the old three installed, remove them: two sets of instructions describing the same product means one of them is out of date.
</Note>

## What the skill adds

ContentHero supplies the tools. The skill supplies the craft of using them well, which is the part a tool schema cannot carry:

- **The order to do things in**, so the agent grounds before it drafts and prices before it spends.
- **The traps that cost money or delete work.** A card's posts and assets are declarative, so a partial update removes what you left out. A slow render is not a failed one, and re-submitting charges you twice.
- **Model prompt craft** specific to our roster, so a prompt is tuned to the model that will run it.
- **Grounded voice synthesis**, the method for drafting copy that sounds like you (see [Voice synthesis](/skills/voice-synthesis)).

It deliberately does **not** restate the tool reference. Your agent already receives every tool's name, description and full schema when it connects, so repeating them would cost context and drift out of date. Parameter detail lives in the [MCP tool reference](/mcp/tools/generate), generated from the published packages.

## Coverage is enforced, not claimed

The skill's CI reads the live tool surface from the published `@contenthero/mcp` and checks it in both directions: every tool the skill names must exist, and **every tool that exists must be named in a workflow**. A build fails if either drifts.

That second direction is the one that matters. Before it existed, the skill named 21 tools that had been renamed away and reached only a quarter of the surface, with two whole domains missing, and nothing could say so.

## The frozen-snapshot model

An installed skill is a snapshot. It does not auto-update; you update it with `git pull` or by re-running the installer. The skill is only instructions. The services it drives (the hosted MCP, the CLI, the model roster, pricing) are server-side and always live.

So the skill bakes in durable guidance (craft, sequence, traps) and defers volatile facts (model ids, prices, platform limits) to live calls. That is what keeps a year-old install correct.

This is also why MCP ranks first in the [auth ladder](/for-ai-agents): it is the only self-updating transport.
